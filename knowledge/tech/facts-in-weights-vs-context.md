# 重み vs コンテキストの事実格納

## 何のための文書か

[構造的事実の1枚](/tech/llm-structural-facts-to-harness-levers.md)の事実4（呼び出し間に状態はない）から出る運用結論「タスク固有の事実は重みでなくコンテキスト（skills・knowledge・RAG）に置け」に対し、「ならファインチューニングで重みに書き込めば？」という反論が来たときに数字で返すための出典。

出会いの経緯: in-context learning を「システムプロンプト→プロンプト最適化→コンテキストエンジニアリング→skills の全パラダイムを貫く共通機構」と総括するブログ記事（2026-08 頃流通）で引用されていた。記事本体の主張は事実4の裏面の再記述であり新規性なしと判定、この実験のみを残差として記録した。

## 実験の要点

出典: Charles O'Neill, "Can a Language Model Learn Facts Continually in Its Weights?" (arXiv:2607.11020, 2026-07, 単著プレプリント)。Qwen3-4B（frozen base + LoRA）に創作事実247件（例: 「-10°C以下で融ける金属 Zorvathine」）を書き込む実験。

- **書き方で応用力が分かれる**: 事実文をそのまま訓練する bare 方式は24ステップで想起97%に達するが応用が弱い。パラフレーズ・QA・含意など24種に展開して訓練する study 方式は、応用+21pt・合成+18pt・反実仮想+29pt 上回る。
- **逐次更新で崩壊する**: 20回の逐次書き込み後、bare 方式の旧事実は保持1%、study 方式でも46%。どの介入策も逐次書き込み下で旧事実の到達可能性を維持できなかった、と論文自身が報告。
- **コンテキストなら回復する**: 忘却した study 事実を文としてプロンプトに与え直すと精度77-80%に回復（bare は14%）。重みから消えたのではなく到達不能になっただけで、コンテキスト供給が到達経路を再建する。

傍証: DeepMind RETRO (2021) — 7.5B パラメータ + 2兆トークンの外部検索で、25倍大きいモデルと同等性能。事実は重みでなく検索（=コンテキスト供給）で持てることの先行例。

## 証拠の限界

【未検証の単一報告】として扱う。Qwen3-4B 単一モデル（8B は一部再現のみ）・創作事実のみ・単著・査読なし・投稿約3週間時点で第三者の追試も言及も見つからない（2026-08-05 に原典照合済み。ブログ記事が引く数値は照合した範囲で全て原典と一致）。数字を意思決定の主根拠にせず、事実4という構造的事実の補強材として使う。

## 使いどころ

- エージェントに SDK 知識・ドメイン事実を持たせる手段の選定で、ファインチューニング案に対し「重み格納は応用・逐次更新に弱い。まず skills / knowledge / RAG」と返す。
- 事実の更新頻度が高い領域（SDK インターフェース等の揮発性知識）ほどコンテキスト側が有利、という優先順位付け。
