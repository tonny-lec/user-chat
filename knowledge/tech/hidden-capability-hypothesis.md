# 相談内容

ジャストアイデア: 世に出ている LLM は実はもっと賢いが、暴走防止・安全利用のためにシステムプロンプト等で制限がかけられているのではないか。だとすれば「ハーネスを外すためのハーネス」を作ることで LLM の能力を最大限に引き出せるのではないか。

# 検討・調査

## 仮説は2つの主張に割れる

- **主張A: 能力の上限そのものが隠されている**（本当はもっと賢いのに蓋がされている）
- **主張B: 発揮を妨げる冗長・過剰慎重が乗っている**（賢さは同じだが出力が削がれている）

B は本物。A は機構を見ると成り立たない。

## A が成り立たない理由 — 安全訓練は蓋ではなく同じ工程の産物

蓋モデルが暗黙に置く順序は「事前学習で天才が完成 → 後から制限をかぶせた」。実際の順序は違う。事前学習が作るのはテキスト続き生成器で、**タスクを保持できない**（要件定義書を渡すと要件定義書の続きを書き始める）。指示追従・タスクの保持・道具の正しい呼び出し・出力の構造化は、すべてポストトレーニングで**付与された**能力。

したがって安全訓練とタスク遂行能力は分離可能な層ではない。外して出てくるのは解放された天才ではなく、ハーネスに一切乗らない素の続き生成器。実測でも jailbreak 状態はタスク遂行の質が落ちる。[構造的事実9つ](/tech/llm-structural-facts-to-harness-levers.md) の言葉では、事実6（完遂への報酬圧）を消すと同時に事実1〜2で使っている条件付けの効きも消す操作にあたる。

## 手元にある反証 — システムプロンプトの実物

[LLMシステムプロンプトの抽出アーカイブ](/tech/llm-system-prompt-archives.md) が証拠になる。GPT-5.6 Sol の約2,660行の内訳は、道具の namespace・citation 義務・広告への言い回し・進捗更新の頻度規定・skills ファイルの読み方 — **製品として動かすための配線がほとんどで、能力に蓋をする記述ではない**。

さらに、システムプロンプトを外して増えるのは能力ではなく自由度。事実3（未指定の自由度は訓練分布の多数派で埋まる）より、外した先に出るのはより賢い出力ではなく**より平均的な出力**。

## ただし A の最強版には測定された真実がある（範囲は狭い）

ポストトレーニングに実測された代償（alignment tax）が確認されている領域はある:

- **キャリブレーションの劣化** — GPT-4 システムカードで、事前学習モデルの方が確信度の較正が良く RLHF 後に悪化したと報告。
- **出力の多様性・エントロピーの低下**。

前者は事実8（能力面はギザギザで自己認識と相関しない）の**起源の説明**になる。自信の言明が較正されていないのは偶然でなく、人間に好まれる応答を最適化した副作用。→ 事実8の機構欄に追記する価値あり。

ただしこれは特定の統計的性質の劣化であって、推論能力・コード品質・タスク遂行のプールが解放を待っているという話ではない。

## B は本物 — ただし全て「指定の追加」で解ける

| 発揮を妨げているもの | 正規の外し方 |
|---|---|
| 推論予算・出力長のデフォルト | effort 設定、明示的な長さ指定（Sol の `Juice: 112` がこれ） |
| ヘッジ・免責・前置きの定型 | プロンプトで抑制指定（[gpt-5.6 エッセンス](/tech/gpt-56-prompting-essence.md)「簡潔指示の削除」） |
| 良性タスクへの過剰慎重（誤検知） | 文脈と権限の明示。バイパスでなく条件付けの追加で解ける |
| 道具・権限の制限 | [サンドボックス](/tech/agent-sandboxing-and-long-running-envs.md) の交換関係。隔離を緩めれば自律時間は伸びる |
| 人間向けの実況・整形 | 出力先が機械なら不要。指定して切る |

重要なのは、これらが全て**制約の除去ではなく指定の追加**で解けること。ヘッジを消すのも過剰慎重を解くのも、やっているのは自由度を減らす方向。

## 最大の未回収能力は逆向きにある

能力の実現量を決めるのは蓋の有無ではなく**条件付けの質**。339ランで観測されたのは「述語＋停止条件＋逃げ道の3点セットで出力が変わる」であって「制限を外したら賢くなった」ではない。

事実9より capability realized = モデルの1手 × ハーネスのループ。未回収分は圧倒的に右側にある。左側の解放を狙う投資は、成功しても掛け算の小さい因子をわずかに動かすだけ。

## 発想の転回 — 外すべきは自分側の死んだ層

「ハーネスを外すハーネス」という着想自体は良い。対象をモデル側から**自分に積み上がった死んだハーネス層**に変えると本物になる。

- 惰性で残る確認ステップ、発火していない skill、誰も読まない CLAUDE.md の行、儀式化した自己チェック。
- これらは事実5（有限コンテキスト）を毎ターン食いながら、判断を1つも変えていない可能性がある。
- [散らかりと干渉](/tech/harness-sprawl-and-interference.md) の淘汰（消して再発するかテスト）に、[観測基盤](/tech/harness-observability-platform.md) の利用観測（発火率・生存率）を接続すれば、字義通り「ハーネスを剥がすハーネス」が実装できる。

# 結論

1. 「賢い素体＋安全の蓋」という順序は誤り。タスク遂行能力自体がポストトレーニングの産物であり、蓋を外すと能力ではなく自由度が増え、事実3により出力は平均へ回帰する。
2. システムプロンプトの実物（Sol 2,660行）は製品配線がほとんどで、能力抑制の記述ではない。仮説の反証として自分の knowledge 内に既にあった。
3. 実測された alignment tax は較正と出力多様性に限定される。前者は事実8（自己認識と能力の非相関）の起源説明として有用。
4. 回収可能な浪費（B）は実在するが、すべて「指定の追加」という正規の栓で解ける。バイパスは不要かつ逆効果。
5. 最大の未回収能力は左側（モデルの1手の解放）ではなく右側（ハーネスのループ）にある。
6. 発想は捨てず対象を転回する — 外すべきハーネスは自分側の死んだ層。発火率・生存率の観測に基づく剥離機構として実装可能。
