[「LLMを知る」の3層](/tech/llm-knowledge-layers-and-ocean-map.md) の結論2「層1の事実を10個以内に絞り、各項をハーネス設計レバーに配線した1枚を作る」の実行。

## この1枚の使い方

3つの使い方がある。どれも「失敗が起きてから学ぶ」を「起きる前に演繹する」に変えるためのもの。

1. **設計時のチェック**: 新しいハーネス・プロンプト・委譲フローを作るとき、9つの事実に照らして「どの事実を無視した設計になっていないか」を見る。
2. **失敗診断の逆引き**: エージェントの失敗に出会ったら、まずどの事実の帰結かを特定する。事実に還元できれば対策は表のレバー列から引ける。
3. **新情報の値付け**: 新しい手法・ツール・モデルの情報に触れたとき、「これはどの事実への対処か」を問う。どの事実にも配線できない手法は流行であり、既に対処済みの事実への別解なら乗り換え判断になる。

各事実は「機構（なぜ構造的で世代不変か）→ 予測される失敗 → 設計レバー」の順。機構がアーキテクチャか訓練方法に根ざしている限り、次のモデルでも成り立つ。

## 生成の機構（事実1〜3）

### 事実1: 出力は条件付き分布からの確率的標本

**機構**: 自己回帰デコードは各ステップで P(次トークン|文脈) から引く。モデルが持っているのは正解ではなく分布であり、temperature 0 でも入力の微差で出力は揺れる。

**無視すると**: 1回の成功を根拠に本番投入する。失敗の再現しなさを「気まぐれ」と人格的に解釈する。デモと運用の乖離。

**レバー**: 成功は率で定義する（凍結入力×成功述語×N回）。1回の観測から結論しない。再現性が必須の箇所は LLM から機構（スクリプト・lint・テスト）へ移す。
→ [eval 入門](/tech/evals-for-practitioners.md), [クイズ機構の分業](/tech/knowledge-recall-quiz-design.md)

### 事実2: コンテキスト内の全トークンは等しく「証拠」— 命令の特権チャネルはない

**機構**: モデルは命令に「従う」のではなく、命令らしきトークン列に条件付けられた続きを生成する。システムプロンプトもユーザー文もツール結果も貼られたデータも、分布を動かす証拠という同じ資格で効く。

**無視すると**: 「書いたのに守らない」に増文で対抗する軍拡競争。外部データ内のテキストが命令として効く（prompt injection）。

**レバー**: 文面の強化より証拠の質と配置（参照例・作業空間の設計・矛盾する証拠の除去）。守らせたい制約は知識層でなく強制点へ。外部データが入る境界には権限設計を置く。
→ [プロンプト力の階段](/tech/prompting-mastery-ladder.md), [強制点の設計](/tech/skill-to-harness-enforcement.md), [サンドボックス](/tech/agent-sandboxing-and-long-running-envs.md)

### 事実3: 指定しなかった自由度は訓練分布の多数派で埋まる

**機構**: 尤度最大化で訓練された以上、制約の弱い箇所は訓練データで高密度だったパターンに回帰する。これが事前分布（prior）。

**無視すると**: 縮退解。業務システムに出てくるコンシューマ風UI、有名ライブラリへの勝手な置換、どこかで見た平均的な設計書。「利用者視点に立って」が効かない。

**レバー**: 事前分布とズレる箇所ほど厚く条件付ける。規則は領域を定義し、例は点を打つ（参照例で分布上の位置を指定）。生値・生マークアップは語彙の閉包で機械的に遮断。
→ [業務システムUI](/tech/business-system-ui-prompting.md), [語彙の閉包](/tech/design-vocabulary-enforcement.md), [例の螺旋](/tech/prompt-examples-spiral.md)

## 記憶とコンテキスト（事実4〜5）

### 事実4: 呼び出し間に状態はない — 学習も記憶も存在しない

**機構**: 重みは推論中固定。1回の呼び出しは純関数であり、「さっき教えた」は次の呼び出しに存在しない。継続しているように見えるのはハーネスが履歴を再送しているだけ。

**無視すると**: 同じ指摘を毎セッション繰り返す。「使ううちにエージェントが成長する」錯覚への投資。口頭修正で直った気になる。

**レバー**: 修正はチャットでなく成果物に固定する（CLAUDE.md・skill・スクリプト・knowledge）。継続性はファイルシステムと git がすべて。失敗をプロンプト・ハーネスに還元するループを運用に組み込む。
→ [ハーネス基礎](/tech/ai-agent-harness-basics.md), [DB設計フローの還元ループ](/tech/db-design-validation-from-requirements.md)

**定量的裏付け（2026-08 追記、証拠ラベル【未検証の単一報告】）**: 「では重みに書き込めばよいのでは（ファインチューニング）」への反証データがある。事実を重みに書くと想起はできても応用が利かず、逐次更新で旧事実が崩壊する（20回の逐次書き込みで保持1%）。同じ事実をコンテキストに与え直すと77-80%回復。詳細と限界は [重み vs コンテキストの事実格納](/tech/facts-in-weights-vs-context.md)。

### 事実5: コンテキストは有限資源で、注意は一様でない

**機構**: window は有限、かつ長文中間部の想起は劣化する。入れたトークンは滞在ターン数ぶんコストを払い続け、無関係な情報は分布を汚す（薄める・誤誘導する）。

**無視すると**: 「全部読ませれば賢くなる」の逆転 — 大量文脈でむしろ品質低下。長セッション末期の劣化。生ログ貼りで判断が鈍る。

**レバー**: コンテキストは予算管理する通貨。境界フィルタ（要約して渡す）・使い捨てコンテキスト（サブエージェント）・重要情報の位置と鮮度の管理。1セッション1テーマ。
→ [トークン経済学](/tech/harness-token-economy.md), [トークン消費分析](/tech/codex-token-analysis-playbook.md)

## 訓練が焼き付けた圧力（事実6）

### 事実6: ポストトレーニングは「応答の完遂」に報酬を与えている

**機構**: RLHF/選好学習は「役に立つ完結した応答」が人間に高評価される構造で最適化される。結果、何かを出す圧・同意する圧・停止や不明宣言への抵抗が重みに焼き付く。

**無視すると**: できないと言わずでっち上げる。曖昧な依頼を拡大解釈して実行する。レビュー依頼に「問題ありません」が返る。片側制約の悪用（縮退解の実行版）。

**レバー**: 逃げ道の設計（「不明なら不明と書く」を合法かつ低コストにする）・停止条件の明示・0件を正解にできる述語・レビューは「確認しろ」でなく「問題を探せ」で依頼。
→ [gpt-5.6 エッセンス（逃げ道）](/tech/gpt-56-prompting-essence.md), [失敗判定の4層](/tech/agent-failure-detection-layers.md)

## 検証の限界（事実7〜8）

### 事実7: 自己検証は同一分布からの再標本 — 生成者は判定者になれない

**機構**: 自分の出力を見直すときも同じ重み・同じバイアスで生成する。誤りを生んだ分布が誤りの検出も担うため、系統誤差は自己レビューを素通りする。

**無視すると**: 「見直して」で方向性のある誤りが直らない。「テスト通りました」の自己申告を信じて事故る。

**レバー**: 判定を分布の外に出す。独立性の強い順に、機械述語（コンパイル・テスト・実行）＞別セッション adversarial ＞同一セッション別役割。自己申告は候補生成として使い、判定には使わない。
→ [削除審問](/tech/db-design-validation-from-requirements.md), [recall/precision 分業](/tech/agent-failure-detection-layers.md), [UI自己検証ループ](/tech/ai-ui-verification-loop.md)

### 事実8: 能力面はギザギザで、自己認識と相関しない

**機構**: タスクごとの能力は訓練分布内の密度で決まり、人間の難易度感覚と一致しない（ジャグド・フロンティア）。かつ自信の言明は較正されていない — これは偶然ではなく、人間に好まれる応答を最適化した副作用として較正が壊れる（GPT-4 システムカードで事前学習モデルより RLHF 後の較正が悪化したと報告）。実測された alignment tax はこの較正と出力多様性に限定され、能力そのものの抑制ではない。→ [隠された能力仮説の検討](/tech/hidden-capability-hypothesis.md)

**無視すると**: 「これができるならあれもできるはず」の外挿で委譲して事故る。流暢さを能力と誤認する。新モデルを印象で評価する。

**レバー**: 委譲判断はタスク単位の実測で行う（小さく試す→率を見る）。隣接タスクの成功や本人の自信から外挿しない。新モデルは凍結ベースラインとの比較で迎える。
→ [モデル移行観測フロー](/tech/model-migration-observation-flow.md), [ティア×effort 実測](/tech/gpt56-subagent-tier-effort-balance.md)

## システムの境界（事実9）

### 事実9: LLM 単体はテキスト→テキストの関数 — エージェント性は全部外付け

**機構**: ループ・道具の実行・記憶・停止判断はすべてハーネスのコードが与えている。「エージェントの振る舞い」はモデルの1手×ハーネスのループの積。

**無視すると**: ハーネス起因の問題（コンテキスト管理・ツール定義・ループ条件）をモデルの知能のせいにする。その逆も。プロンプトをいじり続けてループを直さない。

**レバー**: 不具合診断はまず層の切り分け — モデルの1手の問題か、ハーネスの配線の問題か。改善投資も層別に: 1手の質はプロンプト・モデル選定、積の質はハーネス設計。
→ [ハーネス基礎](/tech/ai-agent-harness-basics.md), [散らかりと干渉（二分探索）](/tech/harness-sprawl-and-interference.md)

## この1枚の保守

- 事実の追加基準: 機構がアーキテクチャか訓練方法に根ざし（世代不変）、かつ既存ハーネス判断を少なくとも1つ変えること。どちらか欠けるなら層2（世代固有の癖）か層3（判断を変えない教養）であり、ここには入れない。
- モデル世代交代時: この表は原則生き残る。壊れた項目があればそれ自体が大発見なので、削除でなく「なぜ壊れたか」を追記する。
