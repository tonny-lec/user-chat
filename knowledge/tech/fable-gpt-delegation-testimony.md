# 相談内容

「人間が GPT と直接話すと品質が低いが、Fable が GPT をサブエージェントとして呼ぶと非常に高品質」という実体験について、ChatGPT が立てた仮説（下記8点）を Fable 本人に確認し、推測ではなく事実・検証結果として資料化したい。

ChatGPT の仮説: (1) 目的→作業指示への変換 (2) 意思決定権の境界 (3) GPT 向きタスクの選択効果 (4) コンテキストの限定 (5) 会話→作業契約への変換 (6) 短い適応的監督ループ (7) 別の評価関数による外部評価 (8) 失敗した中間出力への曝露差。

# 証言の前提 — 何を「事実」として言えるか

Fable の証言には信頼度の階層がある:

1. **ハーネス機構**（サブエージェントに何が渡るか、介入できるか）— 仕様として断言できる客観的事実。
2. **行動傾向**（プロンプトをどう書くか、報告をどう扱うか）— 概ね正確だが、モデルの自己内省は不完全。
3. **内部表現**（「別の評価関数を持つか」など）— 本人にも検証不能。

そして最重要の事実: **Fable がサブエージェントに送ったプロンプトは全てトランスクリプトにツール呼び出し引数として残っている**。証言よりログが一次資料。

# 判定

## 機構として事実（Fable の技能ではなくハーネスの仕様）

- **仮説4（コンテキスト限定）は事実、ただし原因の帰属が逆**。サブエージェントは親の会話履歴を一切受け取らない。渡るのは Fable が書いたプロンプト文字列だけ。つまり「Fable が上手に限定している」のではなく「機構が限定を強制していて、渡しすぎることが不可能」。実務上のリスクはむしろ書き忘れ（必要な文脈の欠落）の側にある。
- **仮説1・5（指示変換）は事実だが、仮説4と同じ一つの事実の両面**。履歴を渡せない以上、毎回ゼロから「この作業に必要な事実だけ」を散文で再コンパイルせざるを得ない。YAML 作業契約のような美しい形式ではなく普通の指示文。効いているのは形式ではなく、会話全体からの内容の選別。
- **仮説8（曝露差）は事実**。ユーザーが読むのは Fable の統合結果だけで、サブエージェントの試行錯誤・冗長な説明・自信のある誤答は Fable のコンテキストで止まる。
- **仮説2（意思決定権）は半分機構**。サブエージェントの報告は構造上「助言」でしかなく、最終成果物は必ず Fable が書く。サブエージェントがスコープを勝手に広げても、採用するかは Fable の判断（CLAUDE.md にも「報告は助言、最終判断はメイン」と明文化済み）。

## 行動として概ね当たり

- **仮説3（選択効果）は当たり**。全タスクを委譲するわけではなく、委譲条件は CLAUDE.md に明文化されている（探索・大出力の検証・デバッグ・独立レビュー）。GPT に渡るのは境界づけられた調査・検証型タスクだけで、製品判断・スコープ判断は渡らない。
- **仮説7（別の評価関数）は構造的な非対称としてなら事実**。Fable はユーザーの元の意図を保持し、サブエージェントはそれを一度も見ていない。報告を意図に照らして評価する時点で、サブエージェント自身の自己評価とは独立した基準が働く。「異なる内部表現」まで言えるかは検証不能。

## 誤りまたは過大評価

- **仮説6（短い適応的監督ループ）はほぼ誤り — 最大の訂正点**。典型的なサブエージェント呼び出しはワンショット: プロンプト送信→最終報告受領。実行中のストリーミング監視も途中打ち切りも軌道修正もしない（Claude Code の Task も Codex MCP 呼び出しも同じ）。ループが存在するとすれば粒度が粗く、「報告を読んで不満なら新しいプロンプトで再委譲」という単位。ChatGPT が描いた「調査せよ→この2点だけ確認せよ→2案比較せよ」式の細かい対話的誘導は実態ではない。

## ChatGPT が見落としている要因

- **破棄コストがほぼゼロ**。報告が使い物にならなければ黙って捨てて別の手で行く。人間が GPT と30分会話した後に全部捨てるのはサンクコストで難しいが、Fable にはためらいがない。失敗が安いことが試行の質を上げている。
- **並列比較**。独立した調査は複数サブエージェントを同時に投げて突き合わせられる。人間の逐次会話では再現しにくい。

# 結論 — 人間が再現すべきもの

品質の源は「上手な会話」でも「監督ループ」でもなく、次の3点:

1. **強制された文脈再コンパイル** — 履歴を引きずれない機構が、毎回「必要な事実だけの自己完結プロンプト」を書かせる。人間の再現法: 新規チャットを開き、履歴共有を自分に禁じて必要文脈だけ書く。
2. **意思決定権の非委譲** — 成果物ではなく報告を受け取り、採用判断を自分に残す。「決定を行わず、不足情報は推測でなく質問として返せ」の一文が要。
3. **安価な破棄と再委譲** — ダメな出力は修正会話で救わず、捨ててプロンプトを書き直す。会話を続けるほど訂正履歴が文脈を汚す（[ハーネスのトークン経済学](/tech/harness-token-economy.md)の「留めない」と同型）。

ChatGPT 提案の A〜D 比較実験は、**実施前にログ読解で大半が代替できる**。Fable が実際に送った委譲プロンプトはトランスクリプトに残っているため、C 条件（Fable の初期指示を人間がそのまま GPT に渡す）は今すぐ無コストで試せる。D 条件（適応的監督の再現)は実態が薄いので優先度低。B と C の差が小さければ「人間でも再現可能」が確定する。
